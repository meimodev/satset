LAN P50 214MS · CLOUD QUEUED
This screen exists for one reason: "did it actually send?" is the question a waiter cannot afford to be unsure about. So the answer is a full screen, not a toast — nothing else is on it, and it cannot be missed on the way past. The station chips resolve in sequence (280ms, 620ms) rather than all at once, so the confirmation reads as work completing rather than a static graphic. Each chip states its own state with a shape, not a colour: a filled tick or a spinner. The latency line is deliberately unglamorous. It is the only place a waiter learns the LAN is healthy, and it says "CLOUD QUEUED" plainly rather than implying the cloud leg already succeeded.

It pops rather than navigates: the table-detail screen below is still mounted and still holds its lock, so re-entering it by go() would dispose and re-acquire for nothing. Tapping "Cetak struk" sets an engaged flag that cancels the 1900ms auto-return — the screen must not yank itself out from under an open printer picker.
