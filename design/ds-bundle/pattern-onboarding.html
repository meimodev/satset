First run — as shipped

mode_select_screen.dart · pair_screen.dart · forbidden_screen.dart

These three screens are not on the design system. They render stock Material 3 with the default purple seed — no context.sat, no SatType, no SatBox. That is a real deviation from “generic Material 3 default” being an explicit anti-reference, and it is the first thing a new install sees. Recorded here as built, not as intended.

The decision itself is sound — one binary question, stated plainly, with the consequence spelled out on each card ("Database lokal di sini"). It is irreversible in practice, and the copy says what each side means rather than naming a mode and hoping. What's wrong is only the skin: default Card, default typography, purple seed.

Pair — /pair

Scan QR dari server tablet, atau isi manual jika multicast diblokir di WiFi:
192.168.1.14

—
The manual path exists because venue Wi-Fi routinely blocks multicast, and the intro sentence says exactly that instead of hiding the fields behind an "Advanced" disclosure. Four raw fields — host, port, one-time token, cert fingerprint — is the honest shape of a self-signed LAN handshake. In practice this screen is bypassed: /pin carries an inline pair flow, and the discovered-server list claims a token automatically on tap. This route is the fallback, which is why it never got styled.
