Loading

Three shapes, chosen by how much is already known

Full-screen — nothing to show yet

Memuat menu…

Used only when the screen has no cached content at all. Always names what is loading — a bare spinner tells a waiter the app is busy but not whether it is busy with the thing they are waiting for.

Skeleton — shape is already known

bg3 blocks on the real card geometry, pulsing 0.5→1 over 1.4s. Preferred over a spinner wherever the layout is predictable, because the page does not jump when data lands. Holds at 0.7 static under reduced motion.

Inline — content is stale, not absent

memuat ulang · angka di bawah masih data lama
A refresh over existing data never blanks the screen. The old numbers stay readable and the spinner sits in the control that caused it — this app's promise is working when the network doesn't, so degrading to "nothing" on a slow request would break that promise on purpose.

Every empty state names the next action in the same breath as the absence: "Pilih dari menu di kiri", "atau pasangkan manual lewat QR", "Hapus filter". An empty state that only reports emptiness is a dead end. Two are distinguished on purpose — nothing exists yet, versus the filter excluded everything. The second gets an escape hatch, because the user's own filter is the cause and they may not remember setting it. No illustrations. A waiter mid-rush does not need a mascot, and a 200KB empty-state graphic is 200KB that does not load on venue Wi-Fi.

Error

Degrade loudly, fail safely

Full-screen — the screen cannot render

☁

The raw exception text is shown, not hidden behind "Something went wrong". The person holding this device is the person who will walk to the server tablet — a real error string is the fastest route there.

Banner — part of the screen failed

⚠ Gagal memuat laporan Coba lagi

Field — the input is wrong

⚠ Email tidak valid.

Transient — the action failed

Gagal kirim: connection refused
Four altitudes, and the tone escalates with the cost, not with the surprise: urgent — the order did not send, the screen cannot render warn — a panel is stale, stock is low, a report failed info — a state changed and you should know No apology copy, no exclamation marks, no personality. "Gagal kirim: connection refused" — the fact, then the next action. A waiter mid-rush is not the audience for a friendly voice. Nothing fails silently: a submit that errors keeps the cart intact and leaves the button live, so the retry is one tap and no re-entry.
